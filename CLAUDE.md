## Conventions

- Anything generated by running code — CSVs, reports, JSON dumps, eval results,
  etc. — goes in `outputs/`, not next to the source that produced it and not in
  `docs/`. The synthetic dataset is the one exception: it's a build input the rest
  of the system depends on, so it lives in `data/sample_docs/` (matching finhive's
  convention for its own sample data), not `outputs/` — but, also matching
  finhive's convention, it's gitignored and regenerated by running
  `python -m portfolio_intel.data.synthetic`, not committed. The generator itself
  (`src/portfolio_intel/data/synthetic.py`) is deterministic (no unseeded
  `random`), so this is safe: anyone who runs it gets byte-identical output.
- **Deterministic-core / LLM-narration split is load-bearing, not a suggestion**:
  every score, duplicate match, value-realization status, and recommendation must
  come from a plain-Python tool function, never be computed or guessed by an LLM
  prompt. If a task seems to require the LLM to "figure out" a number, that's a sign
  the tool layer is missing something — add it there, don't lean on the model.
- This machine cannot reach Databricks. Any code path that needs a live LLM call or
  a live SQL warehouse connection will fail here — that's expected, not a bug to
  chase. Structure new code so the deterministic parts are still runnable and
  testable without that connection (see `prompts/constraints_environment.md`), and
  make LLM/Databricks-dependent failures fail loudly with a clear message, not a
  silent no-op or a raw traceback.
- ADRs for this project start fresh at `docs/architecture/adr/0001-*.md`; finhive's
  17 ADRs live under `docs/architecture/adr/finhive-legacy/` as historical
  reference, not something this project's ADRs are numbered to continue.
- No hardcoded credentials, ever — everything through `.env` (`.env.example` is the
  authoritative list of what this project actually needs; keep it in sync).

## Explicitly out of scope

See `prompts/non_goals.md` for the full list — the two easiest to accidentally
scope-creep back in while implementing:

- No frontend/dashboard/HTTP server — the user's team builds that separately
  against this package.
- No memory/session state, no RAG, no MLflow-served Agent deployment — these exist
  in finhive and it will be tempting to port them "since they're right there"; don't.
